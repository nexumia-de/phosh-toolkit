# Directory Update Log

## 2026-10-25
* **Creation**: [Support for development](support.md) and the decision [support platforms](decisions/support-platforms.md) (issue #11): voluntary support through Liberapay `suitably` (Stripe, statement descriptor `LIBERAPAY.COM`, Radar Lite; verified through `public.json`), Open Collective `nexumia` once a fiscal host accepts it. New `AGENTS.md` rule: every app links the support URL in its metainfo (`url type="donation"`), About dialog, README and `.github/FUNDING.yml`; the example metainfo and this repository's `FUNDING.yml` carry it.
* **Update**: [Flatpak workflow](flatpak-workflow.md): call the reusable workflow as `nexumia-de/phosh-toolkit`; through the old name `suitably/phosh-toolkit` a branch reference failed at startup, only `@main` resolved.
* **Creation**: Decision [release channels from main and tags](decisions/release-channels.md). The reusable [Flatpak workflow](flatpak-workflow.md#release-channels) replaces the rolling release `latest`: `release: true` publishes a pushed tag `v<version>` (checked against the newest metainfo `<release>`), the new input `nightly: true` builds `<app id>.Devel` (`-Dprofile=development`, `-Dbuild_label=<branch> · <commit>`, manifest derived with `--show-manifest`) on every push to the default branch and attaches it to the pre-release `nightly`, serialized and skipped when the branch moved on. Dispatching to the publish repository is its own job. [Shared app repository](app-repository.md) and [toolkit usage](toolkit-usage.md) updated. A label-based nightly slot for pull requests and a long-lived `nightly` branch were considered and rejected.
* **Creation**: [Branch protection](branch-protection.md): `.github/rulesets/main.json` in every repository (pull request with 0 approvals, required CI checks with their exact names, no force push or deletion, admin bypass), imported by the owner because agents cannot change repository settings. `AGENTS.md` asks to keep the file in sync when CI jobs are renamed.
* **Update**: New `AGENTS.md` section "After the task: pull request and CI": agents open a pull request in every repository a finished task changed, watch its CI and fix failures until green, and leave merging to the owner.
* **Update**: [Adaptive libadwaita UI](adaptive-libadwaita.md), `AGENTS.md` and the example metainfo list `pointing` and `keyboard` next to `touch` in `<supports>`. With only `touch` declared, GNOME Software showed "Keyboard not supported" and "Mouse not supported" for Cirro.
* **Update**: Self-test grants `contents: write` to the reusable Flatpak workflow call. Since the release job (which declares that permission) was added, every self-test run had ended in `startup_failure`; a caller must grant at least what the called workflow's jobs declare.
* **Creation**: [Dependency updates](dependency-updates.md), [licensing](licensing.md) and the decision [pinned dependencies](decisions/pinned-dependencies.md). New reusable `update-check.yml` (flatpak-external-data-checker pull requests, GNOME runtime issue); `flatpak.yml` gained a `reuse` job, a licence inventory check (`dependencies-doc`), a licence-file check and source bundles (`--bundle-sources`, `<bundle>-sources-<arch>.flatpak`). Toolkit is REUSE compliant (`REUSE.toml`, `LICENSES/`, GPL-3.0-or-later as declared in the demo metainfo) and has Dependabot for GitHub Actions. New "Dependencies and licences" rules in `AGENTS.md`. Verified locally: flatpak-builder 1.4.2 (Ubuntu 24.04) does not install licence files itself (that came in 1.4.5), meson modules run `post-install` in `_flatpak_build/`, and `--bundle-sources` produces `runtime/<app id>.Sources`.
* **Creation**: [Visual design](design.md) guideline: stock libadwaita styling, colours only via CSS variables, typography via style classes, symbolic icons, feedback patterns, HIG capitalisation, version notes (CSS variables 1.6, `.dimmed` 1.7, not available on the Ubuntu 24.04 host) and a review checklist. Linked from [adaptive libadwaita UI](adaptive-libadwaita.md); new Design section in `AGENTS.md`.
* **Creation**: Decision [code reuse between apps](decisions/code-reuse.md): rule of three, shared runtime code in phosh-toolkit pinned to a tag in app manifests, `examples/` as the skeleton for new apps. New Shared code section and two extra pre-commit checks in `AGENTS.md`; [central toolkit](decisions/central-toolkit.md) lists shared code.
* **Update**: [Flatpak workflow](flatpak-workflow.md) release job deletes `latest` assets the build no longer produces; `--clobber` alone kept the old `io.github.suitably.*` bundles after the rename, and phosh-apps would have published both app ids ([shared app repository](app-repository.md)).
* **Creation**: Decision [domain-based names](decisions/domain-names.md): app ids `de.nexumia.*`, shared repository at `https://flatpak.nexumia.de/` with remote `nexumia`. Renamed the PhoshDemo example and all `MyApp` snippets; [shared app repository](app-repository.md) documents the custom domain; new app id rule in `AGENTS.md`. Moving only phosh-apps to Codeberg was rejected (its terms forbid mostly AI-written projects).
